Hi team — a quick update on the work to connect the consolidated server to the SHR and OpenCR. We've built and verified our half of the integration: once a patient is in the consolidated_db, the SQLMesh pipeline (https://github.com/DIGI-UW/sedish-fhir-pipeline) and FHIR-router mediator (https://github.com/DIGI-UW/fhir-router-mediator) we developed map it and push it on to OpenCR for identity and the SHR for clinical content, and we've run the full test dataset through this successfully. We've also set the iSantePlus instances up to route through the consolidated server as data sources while keeping patient search working, and along the way we found and fixed a bug in the xds-sender module upstream (released as v2.6.1) and bundled it into our image.

The remaining piece is on CHARESS's side — the CDC binlog that captures the EMRs into the consolidated_db. Until that's connected to the consolidated_db we read from, we can't run the full end-to-end test of creating a patient in the EMR and watching it flow through to OpenCR and the SHR. So our half is ready and proven; completing and demonstrating the end-to-end is now gated on CHARESS wiring up the CDC.
