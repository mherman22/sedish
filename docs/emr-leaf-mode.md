Quick update on the iSantePlus / consolidated-server work.

We've moved the iSantePlus instances to a "leaf" model, where the EMRs no longer talk to the HIE directly. The only way data moves up now is through the consolidated server: a patient created in iSantePlus is picked up by CHARESS's binlog CDC, lands in the consolidated_db, and from there our SQLMesh pipeline and the FHIR-router mediator map it and push it on to OpenCR for identity and the SHR for clinical data. The EMR just writes to its own database and the pipeline does the rest. The one thing the EMR still does with the HIE is read — clinicians can still search the registry when registering a patient.

To make that real we had to switch off the old direct-write paths the EMR modules used to fire. On every boot the EMR now blanks three of them: the mpi-client patient feed to OpenCR (on save), its PIX write-back (on import), and the xds-sender clinical/CCD push to the SHR. We deliberately kept the patient-search endpoint and its credentials, so lookups keep working.

Two decisions worth flagging. First, ingestion is now CDC-only — we're no longer running a parallel real-time feed from the EMR into OpenCR/SHR; the consolidated server is the single road in. Second, the xds-sender module used to throw an error whenever its endpoint was left blank, so you couldn't cleanly turn it off — we patched that upstream (merged in IsantePlus as PR #111, released as v2.6.1) and bundled that version into our image.

Where we are: the EMR-side config is done and committed — post-start.sh is wired to leaf-mode, xds-sender 2.6.1 is bundled, and it's all written up.

What's still open: the big one is the CDC link itself — we still need CHARESS's binlog reader pointed at our EMRs' consolidated_db so we can run a true end-to-end test, i.e. create a patient in the EMR and watch it surface in OpenCR and the SHR through the pipeline (the downstream half of that chain is already built and verified). Beyond that, we need to rebuild and redeploy the iSantePlus image so the facilities actually boot into leaf-mode; there's a bug where importing a patient from OpenCR creates two local records (the module pulls in the patient and its golden) that needs fixing; and OpenCR needs a cleanup of the orphaned/duplicate golden records, plus a change to stop the full re-pushes that keep generating them.
